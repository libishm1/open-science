Robotics

ROS 2 on Ubuntu, Universal Robots arms, and a clear path from code generation to simulation before any hardware runs.

No motion on hardware from an agent. The robotics skill generates and checks code and runs simulations. Running a program on a real robot needs an explicit hardware flag, a reviewed program, and a person in charge of the cell.

Platform

  • Use Ubuntu with its matching ROS 2 release: Humble with Ubuntu 22.04, Jazzy with Ubuntu 24.04. Check the pairing in the ROS 2 documentation for your version.
  • The workbench installer works on Ubuntu: ./install.sh --profile coding.
  • Rhino and Grasshopper run on Windows or macOS. Pass poses from them to ROS 2 through a file with stated units, frame and rotation convention.

Example: a pick-and-place waypoint program

  1. Ask for the waypoints. The agent writes each pose with its units, frame, rotation convention and tool offset, in the URScript form global WP_n = p[x, y, z, rx, ry, rz].
  2. It builds the ROS 2 package with colcon build and runs the unit tests (Level 1).
  3. It runs the program against a simulator and records a ros2 bag (Level 2).
  4. You review the bag and the program. Running on the robot is your decision, outside the agent.

Running several agents

Advanced, for scripted runs: work split across several local agents (for example one per package) can use the command-line workbench's shared task queue, which escalates a failed job to a larger model (python -m lawb queue <folder>). Terminal runtimes that host several coding agents, such as Herdr, can run one agent per pane with the same skills.
