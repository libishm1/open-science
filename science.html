Science and bioinformatics

Protein structure work, sequence and single-cell models, publication figures, literature reviews and reproducible analysis, with the skills that ship in the app.

Skills marked upstream come from AIPOCH Open-Science and ship unchanged in this fork. Skills marked fork were added in this fork. Ask the agent for a skill by describing the task; it loads the matching skill.

Example: a protein figure for a paper

  1. Ask: "Make a figure of PDB 1UBQ showing its secondary structure, sized for a two-column journal."
  2. The agent loads molecular-figure-design, confirms the entry with its verify_pdb.py script, renders the structure from the deposited coordinates with matplotlib (no PyMOL needed), and runs check_overlaps.py so labels do not collide.
  3. It fixes the figure to the journal's column width and exports PDF and SVG with live text, and TIFF at 600 dpi. Check the figure against the claim it supports before using it.

Structure prediction models need a GPU. If your computer has none, use the upstream remote-compute-ssh skill to run them on a server, and compute-env-setup to prepare that environment.

Example: screening counts and a PRISMA diagram that a reviewer can check

  1. Keep one row per record in a spreadsheet saved as CSV, with the columns record_id, strand, year, type, duplicate, stage, decision, reason.
  2. In the app, attach the CSV and ask: "Count my screening results and draw the PRISMA flow."
  3. The agent runs the research-synthesis helper and returns the counts and a flow diagram (flow.svg). Every number is computed from your rows, so a reviewer can re-derive it.

Figures and paper narrative

For data figures, the upstream figure-composer, figure-style and paper-narrative skills cover multi-panel layout, legibility rules and the story across a figure deck.

Proofs and verified methods

For a method with mathematical guarantees, lean-verification (fork) gives the procedure for proving results in Lean 4 with Mathlib, with an honesty rule (proved, cited axiom, or prose, never sorry), CI gates, and property tests that check the real code against each proven invariant.

Good practice

  • Keep raw data read-only and record every transformation in the notebook.
  • Ask the agent to cite the file and line, or the paper and page, behind each claim.
  • Use a local model for anything that includes unpublished data.
